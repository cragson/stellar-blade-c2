# Stellar Blade: C2

**A command center for your Stellar Blade save. Change items, outfits, upgrades, skills, camps, quests,<br>
even where you are in the story, or type the developers' own console commands. Right in your browser.**

### [Open C2](https://cragson.github.io/stellar-blade-c2/)

Nothing to install. Your save never leaves your computer. Free and open source.

## Three steps

| 1. Back up | 2. Edit | 3. Play |
|---|---|---|
| Quit the game and copy your save somewhere safe. | [Open C2](https://cragson.github.io/stellar-blade-c2/) and drop your save onto it. Change whatever you like: everything you change turns **gold**. | Click **Download save**, put the file in place of the old one and load it in the game. |

**Where is my save?** The file is called `StellarBladeSave00.sav`, in the numbered folder inside:

**Windows** (paste it into the Explorer address bar)

```
%LOCALAPPDATA%\SB\Saved\SaveGames\
```

**Steam Deck and Linux**

```
~/.local/share/Steam/steamapps/compatdata/3489700/pfx/drive_c/users/steamuser/AppData/Local/SB/Saved/SaveGames/
```

C2 shows both folders too, with a copy button.

### The developers' console, rebuilt

Stellar Blade ships with about 670 developer console commands, but their code was taken out of the
released game, so typing them does nothing. C2 rebuilds the ones that only change your save. Type `SB` in
the search field (press <kbd>/</kbd> to jump there) or on the **Commands** page: C2 suggests the commands
and then their arguments, with English names. Every command lands in the sidebar like a click would.

```
SBPlayerSetLevel weapon 40
SBPlayerEquipItem NanoSuit true BS_Nier_01
SBTurntableUnlock all
SBCheatGroup S_Enforce5
```

The **Commands** page also shows every change you've made as commands you can copy or download, and runs
a saved command file again, on any save. Its catalog lists **all 668 developer commands** (with their
parameters, what C2 can do with each, how often the developers used it, and their real example lines)
and **all 3,033 developer command sets**, searchable, with a run button for the ones a save file can do. Commands tagged **dev** are the developers' own;
**C2** marks the few that C2 adds for things that had no console command.

<img src="screenshots/commands.webp" alt="The Commands page: typing SBPlayerEquipItem NanoSuit true Nier suggests the NieR nanosuits you own">

## How to read the screen

<img src="screenshots/legend.svg" alt="Key: a blue check means it's in your save; a dashed tile with a + means you don't have it yet; gold means it will change when you download; a lock means it can't be changed; a ticket means an edition or DLC item; a flask means experimental">

The colours mean the same thing on every page. **Blue** is your save as it is. **Gold** is what the
download will change. Every gold change is also listed in the sidebar, where each one has its own undo.
Hover over anything (or long-press it on a phone) to see what it is and what it does.

## Safe by design

- **Private.** Everything happens in your browser. No uploads, no accounts, no tracking, and the page
  doesn't make a single network request.
- **Checked.** Every edited save is read back and its checksum verified before you can download it.
  Everything you didn't change stays byte for byte the same.
- **Plays by the game's rules.** The game reacts to events, not only to what's stored: a can only shows up
  in the camp vending machine, a fish in the Album, a design pattern in a shop once the game has "seen" you
  pick it up. C2 replays those events for everything it changes, so rewards and unlocks follow
  just like in the game.
- **Within the game's limits.** Amounts are capped at the game's own maximums.
- **Hands off your trophies.** Trophies are shown, never changed.
- **No spoilers.** Story chapters and main quests you haven't reached stay hidden unless you ask.

## Good to know

- It works with the **PC version** (Steam). PlayStation saves are encrypted.
- **Edition and DLC items** (Deluxe and Complete Edition, pre-order bonuses, the NieR:Automata and NIKKE
  collaborations) are marked with a ticket. You can add them, but the game checks your purchases and only
  shows them if you own them.
- **Experimental** options (marked with a flask) haven't been tested in the game yet: story jumps, camps
  in areas you haven't visited, teleporting, side quest steps, unlocking skill trees early, moving Eve back
  to her camp, marking all endings as seen, and the New Game+ switch. Keep your backup and check the result
  in game.
- Story jumps only go forward. Skills, upgrades, gear and side quests stay as they are.
- The New Game+ switch only changes the counter the game's New Game+ checks read. The New Game+ trophy
  is left alone.
- If Steam reports a Cloud conflict after you replace the save, keep the file on this computer.
- The game keeps its own previous copy of your save in the `Backup` folder next to it.

## Questions

<details>
<summary><b>My cans don't show up in the camp vending machine.</b></summary>
<br>
The game only counts cans it saw you pick up. If another tool added them, click the tag badge on the
<b>Cans</b> ring on the Overview (or use <b>Tools → Picked-up items</b>) and download. Cans you add with
this editor are registered automatically.
</details>

<details>
<summary><b>I added a DLC outfit, but it isn't in the game.</b></summary>
<br>
Items marked with a ticket belong to an edition or DLC. The game only shows them if your account owns
that edition or DLC.
</details>

<details>
<summary><b>Can I undo a change?</b></summary>
<br>
Before you download, yes: every change in the sidebar has its own <b>×</b>, and the bin discards
everything. After you've replaced the file, put your backup back.
</details>

<details>
<summary><b>Does it change the game itself?</b></summary>
<br>
No. It only edits the save file you give it. It doesn't touch the game, its files or Steam.
</details>

<details>
<summary><b>Which developer commands work?</b></summary>
<br>
Those that change what's stored in a save: items, upgrades, skills, difficulty, camps, side quests,
story jumps, what Eve wears, Album and Boss Challenge unlocks, shop levels, music and the tools. Commands
that need the running game (god mode, spawning enemies, camera tricks) can't work in a save file.
C2 refuses on purpose to change trophies, to complete story achievements outside a story jump, and to
fake DLC purchases. The developers' sets only ever raise levels, never lower them.
</details>

<details>
<summary><b>Why does it show symbols instead of the game's item pictures?</b></summary>
<br>
The game's artwork can't be shipped with C2. You can make an icon pack from your own copy of the
game, see <a href="#item-icons-and-map-art-optional">Item icons and map art</a> below.
</details>

## Item icons and map art (optional)

C2 can show the game's own item icons, and the game's own maps of the Wasteland, Great Desert and
Xion (surface and underground) under the Map. They're the game's artwork, so they aren't part of
this project: you make a pack from your own copy of the game, and load it in C2.

1. Install [Rust](https://rustup.rs) once, then build the small decompressor:
   `cd tools/icon-pack/oodec && cargo build --release`
2. Make the pack: `python3 tools/icon-pack/make_icon_pack.py "<your Stellar Blade folder>"`
   (the folder that contains `SB/Content/Paks`; common Steam locations are found automatically).
   This writes `StellarBladeIcons.json`: 700+ item icons and 4 world maps, about 20 MB
   (`--no-maps` leaves the maps out, about 4 MB).
3. In C2, go to **Tools → Item icons and map art → Load**. The pack stays in that browser.

The pack also carries the game's texts (`--lang de` and 21 more languages, `--no-texts` to leave them
out): C2 uses them for the longer writing it doesn't ship itself, such as enemy descriptions, dialogue
lines, the manual and the loading tips.

Please don't share or upload the pack: it contains the game's artwork.

## For the curious

<details>
<summary><b>How it works</b></summary>
<br>

A Stellar Blade PC save is `EVAS` + a version number + an Unreal Engine 4.26 *GVAS* SaveGame
+ a CRC32 checksum of the GVAS part. [`gvas.js`](gvas.js) reads the GVAS tagged properties
into plain objects and writes them back byte for byte. Anything that isn't edited comes out
identical to what was read. [`model.js`](model.js) knows where things live:

| What | Where in the save |
|---|---|
| Items | `DataMap_SBItem["Item"].Inventory[]`, one `FSBItemInstance` (`ItemAlias`, `ItemCount`, `ItemChargeCount`, ...) per item |
| Items ever obtained | `DataMap_SBItem["Item"].ItemOtaineSet` |
| Skill points, upgrade levels | `DataMap_SBActor["PlayerActor"].SP`, `.LevelArray` |
| Difficulty, endings | `DataMap_int32["GameDifficulty"]` (Normal 0, Story 1, Hard 2), `DataMap_int64["EndingTimeStamp_*"]` |
| Skills | `DataMap_SBAcquisitionSkill["AcquisitionSkill"].AcquisitionSkillList` |
| Camps | the camp's objects in `DataMap_SBEnv["Env"].ZoneContainerList[].ZoneEnvStorageList` |
| Quests | `DataMap_SBQuest["Quest"]`: `ProgressQuestList`, `CompleteQuestList`, `TrackingQuestAliases` |
| Album, Boss Challenge, trophies | `SBAchievement.AchievementList` |
| Story progress | `GamePlayProgressRecordData.ProgressRecordGroup`: every progress record with a done flag |
| What Eve wears | `DataMap_SBActor["PlayerActor"].Equipment` (slot = `ESBEquipType`), plus each item's `Equiped` flag |
| Shop levels | `SBShopHistory.FriendShip`: `TotalFriendShip`, `FriendShipLevel` |
| Camp music | `DataMap_FString["TurntableSoundAlias"]` |
| Tutorial pop-ups seen | `SBHint.CompleteHintList` |
| New Game+ | `DataMap_int32["NewGamePlusPlayCount"]` |

New items are created by copying an existing entry of the same category, with fresh GUIDs.
[`progress.js`](progress.js) handles everything on the progress pages, and [`commands.js`](commands.js)
turns the developers' console commands into the same changes. The interface is
[`ui.js`](ui.js) (icons, tooltips, gauges), [`app.js`](app.js) (state, items, overview, changes) and
[`pages.js`](pages.js) (the progress pages).

**Game events.** In the game, picking up an item, levelling up, learning a skill, switching an object, finishing
a quest or defeating an enemy fires an event, and every achievement whose conditions match moves forward. The
vending machine's can collection, the Album, shop unlocks, story unlocks and reward skills all hang off those
achievements. Changing the save alone skips all of that, so C2 replays the same events from the game's
achievement table (`AchievementTable`) for everything it changes, including the chain reactions: rewards,
achievements that feed others, achievements waiting on others. Steam trophies are the one thing it leaves alone.

**Story jumps** ([`chapter.js`](chapter.js)) do what the developers' progress tools do, which are
switched off in the released game: they replay the game's progress records up to the chosen point. Each
record says what a quest step changes in the world: the state of a door, lift or switch, a trigger that has
fired, a story achievement. Some records also carry story commands (start or finish a helper quest, give or
take a story item). Their skill, level and gear presets are left out. The main quests are then rebuilt with
their task groups, and Eve is placed at the chapter's starting point. Objects and spawn points in areas
the save hasn't visited get their positions from the game's level files. [`items.js`](items.js),
[`gamedata.js`](gamedata.js) and [`chapters.js`](chapters.js) hold names and links taken from the game's data
tables (item, camp, quest, skill, album, trophy, shop, music and upgrade tables) and its English text.

</details>

<details>
<summary><b>Development</b></summary>
<br>

No build step and no dependencies: it's plain HTML, CSS and JavaScript.

```sh
python3 -m http.server     # then open http://localhost:8000
node --test tests/unit.test.js
SB_SAVE=/path/to/StellarBladeSave00.sav node --test tests/unit.test.js   # also test a real save
node tests/e2e.mjs --save /path/to/StellarBladeSave00.sav               # full browser test (needs Chromium)
```

The page has a strict Content-Security-Policy, so keep all scripts and styles in separate files
(no inline `<script>` or `style=`), and build the interface with DOM calls, never `innerHTML`.

**Publishing on GitHub Pages:** in the repository go to **Settings → Pages → Build and deployment**, set
**Source** to **Deploy from a branch** and pick `main` with the folder the site is in (`/ (root)` for this
layout). The site is plain static files, so there's no build step. Run the tests before you push.

</details>
